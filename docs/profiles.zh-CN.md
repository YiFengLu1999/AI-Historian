# 执行 profile

AI Historian 采用同一套语义方法，但有两种执行版本。二者共享相同的证据表示和 A1–A9 职责，区别主要在于运行时如何限定跨文档材料的范围。

| 对比项 | 实验版 | 可扩展全文版 |
| --- | --- | --- |
| 包内位置 | `ai_historian.profiles.evaluation` 与 `experiments/` | `ai_historian.profiles.scalable_fulltext` |
| 主要目的 | 复现论文的控制实验 | 为 Westlake Historian 工作流处理完整文本 |
| 输入范围 | 为实验一、实验二准备的限定案例 | 全文和多文档集合 |
| 跨文档范围 | 候选范围已经较小且受控 | 运行时从全文检索并构建小型 `episode_packet` |
| A8 核验 | 基于引文与上下文的 10B 判断 | 在检索得到的小范围内调用同一个核心 10B，再将证据合并回全文 |
| 命令 | `uv run aih` | `uv run aih-fulltext` |
| 工程重点 | 实验一致性与冻结结果追踪 | 上下文可扩展性、召回、断点续跑和应用导出 |
| 论文指标 | 由冻结实验材料直接呈现 | 通过实验版进行引用 |

## 共同方法

两种版本都保留原始句子和稳定标识符，构建 TimeBlock，分别处理叙事顺序与编年顺序，在传播时间约束之前核验候选跨文本关系，并把通过核验的证据规范化为可追溯的时间范围。因此，A1–A9 的语义角色保持一致。

## 全文版本如何处理上下文限制

平台版通过新增的 runtime-scope 层为 A8 提供有界输入范围：

1. 读取完整的 Step 10 TimeBlock 输出；
2. 通过词法相似度或可选的 embedding 相似度检索跨文档候选窗口；
3. 构建范围紧凑、包含时间锚点和有限邻近上下文的 `episode_packet`；
4. 创建临时小范围运行目录，并调用相同的核心 10B 证据核验阶段；
5. 对通过核验的证据去重并合并回原始全文 TimeBlock；
6. 继续执行单文档稳定、时间图传播、A9 规范化和应用导出。

这一面向上下文管理和平台部署的工程调整完整保留 AIH 的历史证据方法。

## 指标解释边界

论文实验一的核心结果——六个《史记》案例、244 个有效范围上的 86.2% MicroIoU——来自归档的实验版。实验二用于诊断结构化中间推理。全文版的公开目的是让读者把相同方法应用于更长语料；比较结果时必须明确两种执行版本的工程差异。
